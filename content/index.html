A tangible token model on Bitcoin

Tokens with Bitcoin at their core.

DUST-20 connects every token unit to an explicit amount of satoshis. Supply, ownership and movement all live inside Bitcoin's own UTXO model — and this site lets you build, validate and visualize all of it in your browser.

What is DUST-20?

A way of representing fungible tokens on Bitcoin where each unit is tied to a fixed number of satoshis, so the token and the bitcoin carrying it move together.

01 / THE IDEA

A unit is a measured piece of bitcoin

A deploy declares how many satoshis stand behind one unit. That number never changes, so any unit of that ticker always occupies exactly the same amount of Bitcoin.

02 / THE CARRIER

Ownership is an unspent output

There are no balances or accounts. You own units because you control the UTXO whose satoshis carry them — the same thing that makes you own bitcoin.

03 / THE MOVEMENT

Sending is an ordinary spend

There is no transfer message. You move units by spending the satoshis that hold them, which means the transaction you build is the transfer.

Why it matters

Why satoshis matter here.

In most token systems the amount is just a number in a message. In DUST-20 the amount is physically present in the transaction as bitcoin.

The amount is verifiable without trusting anyone

If a ticker is backed at 546 satoshis per unit, then 91 units occupy exactly 49,686 satoshis. Anyone can check that number against the raw transaction — it is not a claim in a database.

It also means satoshis can be lost

Because the units live in the satoshis, anything that happens to those satoshis happens to the units. Pay them to a miner as a fee and the units are destroyed. This is the single most important thing to understand before you send.

!

Sending part of your balance requires a change output

If you hold 91 units and send 10, the remaining 81 need their own output. Leave it out and those 81 units are burned — Bitcoin will confirm the transaction normally and nothing will warn you. The transaction visualizer shows exactly what happens.

The object

What is a DUST-20 UTXO?

An ordinary Bitcoin output that an indexer has determined carries token units, because of where its satoshis came from.

Bitcoin sees an ordinary output

There is no special script, no metadata attached to the output, and no way for a Bitcoin node to tell the difference. A DUST-20 output is a normal output holding a specific number of satoshis.

The colour is an interpretation

Software follows the history: a mint created units in an output, and every spend since then moved those satoshis. Anyone applying the same rules to the same chain reaches the same answer — but it is a reading of Bitcoin, not something Bitcoin enforces.

Because the interpretation depends on which satoshis went where, the order and size of a transaction's outputs decide the result. That is why building a DUST-20 transaction is different from building an ordinary payment.

The operations

Deploy, mint and transfer.

Only two of these are messages you write. The third is something you do with a Bitcoin transaction.

Deploy

Creates a ticker and fixes its satoshi backing rule.

Mint

Creates units in an output matching the declared backing.

Transfer

An ordinary Bitcoin spend. There is no transfer inscription.

Burn

A derived outcome when satoshis carrying units are lost.
